# Routing and data in the web app

The web app (`apps/web`) runs on [TanStack Start](https://tanstack.com/start)
with TanStack Router (file routes) and TanStack Query.

## Layout

- `app/routes/` — file routes. `routeTree.gen.ts` is generated by the Vite
  plugin on `dev`/`build` and committed; do not edit it.
- `app/routes/__root.tsx` — document shell, head tags, error and not-found
  pages.
- `app/router.tsx` — `getRouter()`: one `QueryClient` per request/browser
  session, SSR query integration, and the per-request script nonce.
- `app/server.ts` — server entry. Adds the security headers and the
  `Content-Security-Policy` with a fresh nonce, which it hands to the router
  through the request context.
- `app/lib/public-api.ts` — server functions for anonymous public reads
  (event, discovery, organizer, sitemap). Loaders call these, so public data
  is always read on the server, on the first render and on client navigation.

## Routing rules

- Import routing from `@tanstack/react-router`, never `react-router`.
- Links: `<Link to="/events/$eventId/sellers" params={{ eventId }}>`. Plain
  paths without params can be strings: `<Link to="/dashboard">`. A button
  that navigates: `<Button asChild><Link …/></Button>`.
- Navigate in code: `const navigate = useNavigate(); navigate({ to: "/settings", replace: true })`.
- Params inside shared components: `useParams({ strict: false }).eventId`.
- Search params inside shared components: `useSearch({ strict: false })`, or
  `Route.useSearch()` in a route file. Routes that read search params declare
  `validateSearch` (see `routes/discover.tsx`, `routes/sign-in.tsx`).
- To read or replace the current URL's query string imperatively (for
  example removing a token from the address bar), use
  `navigate({ to: ".", search: …, replace: true })`.
- Forms that used React Router's `<Form method="get">` become a normal
  `<form>` whose submit handler calls `navigate({ to, search })`.

## Data rules (TanStack Query)

- Signed-in reads use `useQuery`. Keys start with the account:
  `accountKey(accountId, "events", eventId)` from `lib/use-account-data.ts`,
  where `accountId` comes from `useExpectedAccountId()`. That keeps one
  account's cache away from another's; sign-out also clears the cache.
- Writes use `useMutation`; on success, update the cache with
  `queryClient.setQueryData` or call `queryClient.invalidateQueries` for the
  keys the write changed.
- Keep the API calls, their order and the error handling the component had:
  the same messages, roles and retry buttons. Query defaults: one retry,
  30 s stale time, refetch on window focus. Set `retry: false` where a retry
  would repeat a user-visible error or a rate-limited call.
- One-off effects that are not reads (verifying a link, a countdown) stay
  ordinary effects or mutations.
- The public map keeps its own manifest, safety-feed and offline loader
  (`usePublicStops`): it has polling, ETags and an offline store that Query
  would not improve.

## Tests

- Unit tests render with `await renderWithRouter(<Component />, { path, url })`
  from `app/test/render.tsx`: a real router plus a fresh query client.
  `path` is the route pattern (e.g. `"/events/$eventId"`), `url` the address.
- Prefer `findBy…` after render: queries resolve asynchronously.
